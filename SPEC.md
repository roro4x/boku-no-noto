# 僕のノート — функциональная спецификация

## 1. Область первой версии

Первая версия состоит из публичной домашней страницы, справочного раздела 日本語 · N5 и Markdown-архива японских текстов. Сайт статический, не требует входа и не хранит персональные данные посетителя.

Вне области: фотословарь, соло-RPG, CMS, редактор заметок, регистрация и серверная часть.

## 2. Маршруты

Используется hash-routing, совместимый со статическим хостингом:

```text
#/                                  главная
#/nihongo/grammar                   грамматика
#/nihongo/vocabulary                слова
#/nihongo/kanji                     кандзи
#/nihongo/:category/:itemId         подробная карточка
#/texts                              архив японских текстов
#/texts/:slug                        Markdown-публикация
```

Поисковый запрос хранится в параметре `q`, чтобы ссылку можно было скопировать, а возврат из карточки восстанавливал список.

## 3. Навигация

Общее боковое меню содержит только:

- Главная;
- 日本語 · N5.
- 読みもの · Тексты.

Грамматика, слова и кандзи доступны во внутренней навигации раздела 日本語 · N5. Активная ссылка имеет `aria-current`.

Оболочка сайта переключается между русским и японским. Выбор хранится локально под ключом `boku-no-noto-locale`, обновляет `html[lang]` и не переводит пользовательские Markdown-публикации, русские значения учебного набора или другие данные контента.

## 4. Каталог 日本語 · N5

### Категории

Каждая категория загружает собственный JSON-файл. На внутренних ссылках показывается число записей из manifest.

### Поиск

- работает по мере ввода;
- нормализует Unicode через `String.prototype.normalize('NFKC')`;
- не зависит от регистра русского и латинского текста;
- ищет по японскому написанию, чтению, русскому значению и доступным пояснениям;
- пустой запрос показывает все элементы категории;
- нулевой результат предлагает очистить запрос.

### Порядок и порционная выдача

Используется порядок `order` из набора данных. Первые 40 элементов отображаются сразу, следующие открываются кнопкой «Показать ещё 40».

### Подробные карточки

**Грамматика:** конструкция, русское значение, пояснение и примеры с переводом.

**Слова:** написание, чтение, значения и часть речи.

**Кандзи:** знак, русские значения, онъёми, кунъёми и примеры слов.

Каждая карточка имеет прямой URL и ссылку возврата к списку.

## 5. Модель учебных данных

### Общие поля

```ts
type BaseItem = {
  id: string
  sourceRefs: string[]
  order: number
}
```

### GrammarItem

```ts
type GrammarItem = BaseItem & {
  pattern: string
  meaningRu: string
  explanationRu: string
  examples: Array<{
    textJa: string
    reading?: string
    translationRu: string
  }>
  tags?: string[]
}
```

### VocabularyItem

```ts
type VocabularyItem = BaseItem & {
  term: string
  reading: string
  meaningsRu: string[]
  partOfSpeech: string
}
```

### KanjiItem

```ts
type KanjiItem = BaseItem & {
  character: string
  meaningsRu: string[]
  readings: { on: string[]; kun: string[] }
  examples: Array<{
    term: string
    reading: string
    meaningRu: string
  }>
}
```

### Manifest

Manifest содержит `schemaVersion`, `datasetVersion`, язык интерфейса, уровень, количество записей по категориям и идентификаторы источников.

## 6. Качество данных

- идентификаторы стабильны и уникальны;
- порядок внутри категории уникален;
- каждая запись связана хотя бы с одним источником;
- обязательные русские и японские поля не пусты;
- примеры грамматики и кандзи проходят структурную проверку;
- смена набора повышает `datasetVersion`;
- каталог нигде не называется официальным исчерпывающим перечнем JLPT.

Текущая версия `2026-09-openjlpt-1` содержит 20 грамматических конструкций, 662 слова и 79 кандзи. Источники: OpenJLPT, JMdict и KANJIDIC2.

## 7. Markdown-архив

Файлы находятся в `content/texts/*.md` и подключаются на этапе сборки через `import.meta.glob`. Обязательный frontmatter:

```yaml
---
title: 雨の日の散歩
date: 2026-09-18
description: Краткое описание для списка.
---
```

- `title` участвует в поиске и отображается как заголовок;
- `date` имеет формат `YYYY-MM-DD` и используется для сортировки и отбора;
- `description` необязателен;
- имя файла без `.md` становится стабильным slug;
- сырой HTML из Markdown не исполняется;
- GFM-таблицы и типографические элементы адаптируются к узкому экрану.

Список сортируется от новых публикаций к старым. Параметры `q`, `year` и `month` сохраняются в URL и восстанавливаются при возврате из публикации.

## 8. Состояния интерфейса

- загрузка manifest и выбранной категории;
- готовый список;
- пустой поисковый результат;
- ошибка чтения данных с повторной попыткой;
- подробная карточка существующей единицы.
- пустой архив или пустой результат отбора;
- отсутствующая Markdown-публикация с возвратом к списку.
- готовый музыкальный плеер, воспроизведение, остановка и ошибка чтения аудиофайла.

## 9. Музыкальный плеер

- источник: `public/audio/mirostar-lofi-beats-531504.mp3`;
- воспроизведение начинается только после действия пользователя;
- доступны запуск, остановка со сбросом позиции и громкость;
- дисплей показывает название записи, текущую позицию и длительность;
- ошибка загрузки объясняется на выбранном языке интерфейса.

## 10. Доступность

- семантические `header`, `nav`, `main`, `aside`, `footer`;
- skip-link переводит фокус на `main`;
- видимые подписи полей;
- `lang="ja"` на японских фрагментах;
- заметный `:focus-visible`;
- элементы управления не меньше 44 CSS px на mobile;
- компоновка работает при 320 px и увеличении текста до 200%.

## 11. Производительность

- manifest загружается один раз вместе с выбранной категорией;
- JSON других категорий не загружается до перехода;
- большая категория выдаётся порциями по 40 элементов;
- изображения и шрифты не должны блокировать чтение каталога.
- Markdown-файлы входят в статическую сборку и не требуют запроса к серверу во время чтения.

## 12. Проверки

- unit-тесты нормализации и поиска по русскому, кандзи и кане;
- unit-тесты frontmatter, поиска по заголовку и отбора по датам;
- unit-тесты локалей и форматирования дат;
- проверка схемы, количества, ID, порядка и ссылок на источники;
- TypeScript check;
- production build;
- механическая проверка дизайн-анти-паттернов.
