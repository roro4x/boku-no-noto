# 僕のノート — функциональная спецификация

## 1. Область первой версии

Первая версия состоит из публичной домашней страницы, словаря Kaishi 1.5k, Markdown-архива моих текстов, личных Markdown-заметок, библиотеки промптов и каталога внешних ссылок. Сайт статический, не требует входа и не хранит персональные данные посетителя.

Вне области: фотословарь, соло-RPG, CMS, редактор заметок, регистрация и серверная часть.

## 2. Маршруты

Используется hash-routing, совместимый со статическим хостингом:

```text
#/                                  главная
#/words                            словарь Kaishi
#/words/:itemId                    подробная карточка слова
#/texts                              мои тексты
#/texts/:slug                        Markdown-публикация
#/notes                              список личных заметок
#/notes/:slug                        просмотр Markdown-заметки
#/prompts                            библиотека промптов
#/prompts/:id                        просмотр промпта
#/links                              каталог внешних ссылок
```

Поисковый запрос хранится в параметре `q`, чтобы ссылку можно было скопировать, а возврат из карточки восстанавливал список.

## 3. Навигация

Общее боковое меню содержит только:

- Главная;
- Слова · Kaishi;
- Мои тексты / 私の文章;
- Заметки / ノート;
- Промпты;
- Ссылки.

Активная ссылка имеет `aria-current`.

Оболочка сайта переключается между русским и японским. Выбор хранится локально под ключом `boku-no-noto-locale`, обновляет `html[lang]` и не переводит пользовательские Markdown-публикации, русские значения учебного набора или другие данные контента.

## 4. Словарь Kaishi 1.5k

Список загружается из `public/data/kaishi/vocabulary.json`. Поиск по написанию, чтению и русскому переводу нормализует NFKC, регистр и пробелы. Пустой запрос показывает все 1500 слов в порядке колоды, по 40 записей. Карточка содержит чтение, перевод, пример с переводом и русское примечание, если оно есть. Предусмотрены загрузка, ошибка с повторной попыткой, пустой поиск и неизвестное слово. Главная использует тот же JSON.

## 5. Модель слов

```ts
type VocabularyItem = {
  id: string
  order: number
  term: string
  reading: string
  meaningsRu: string[]
  sentence: string
  sentenceMeaningRu: string
  notesRu: string
}
```

## 6. Качество данных

Импорт `scripts/import-kaishi.py` читает предоставленный пакет Anki, преобразует HTML в обычный текст и сохраняет 1500 записей со стабильными ID на основе ID заметок. Метаданные исходного файла и SHA-256 находятся в `source.json`. Медиафайлы не импортируются. `npm run data:validate` проверяет число записей, уникальность ID, порядок и обязательные поля.

## 7. Markdown-архив

Раздел «Мои тексты» содержит только личные файлы из `content/texts/*.md`, подключаемые на этапе сборки через `import.meta.glob`. Обязательный frontmatter:

```yaml
---
title: 雨の日の散歩
date: 2026-09-18
description: Краткое описание для списка.
---
```

- `title` участвует в поиске и отображается как заголовок;
- `date` имеет формат `YYYY-MM-DD` и используется для сортировки и отбора;
- `description` необязателен;
- имя файла без `.md` становится стабильным slug;
- сырой HTML из Markdown не исполняется;
- GFM-таблицы и типографические элементы адаптируются к узкому экрану.

Список сортируется от новых публикаций к старым. Параметры `q`, `year` и `month` сохраняются в URL и восстанавливаются при возврате из публикации.

## 8. Личные заметки

- файлы находятся в `content/notes/*.md` и используют тот же frontmatter, что архив текстов;
- список показывает название, краткое описание и дату;
- отдельная страница безопасно отображает GFM Markdown без выполнения сырого HTML;
- содержимое заметок не переводится при смене языка интерфейса;
- заметки добавляются через файлы проекта без CMS и браузерного редактора.

## 9. Библиотека промптов

- исходные файлы находятся в `content/prompts/*.md` и подключаются через `import.meta.glob` с запросом `?url` как отдельные статические ресурсы;
- метаданные и порядок задаются в `src/data/prompts.ts`;
- список ищет без учёта регистра по названию, описанию и тегам;
- подробная страница загружает исходный файл и отображает GFM Markdown;
- сырой HTML не интерпретируется и произвольный JavaScript не выполняется;
- исходный `.md` можно скачать без изменения содержимого;
- отсутствующий или повреждённый файл показывает понятную ошибку с повторной попыткой;
- браузерного добавления, редактирования и удаления нет.

## 10. Каталог ссылок

- записи задаются в `src/data/links.ts`;
- локальные баннеры хранятся в `public/assets/banners` и имеют размер 88×31;
- внешний адрес показывается текстом и открывается в новой вкладке;
- внешние ссылки используют `target="_blank"` и `rel="noopener noreferrer"`;
- добавление новой записи не требует изменения компонента.

## 11. Состояния интерфейса

- загрузка manifest и выбранной категории;
- готовый список;
- пустой поисковый результат;
- ошибка чтения данных с повторной попыткой;
- подробная карточка существующей единицы.
- пустой архив или пустой результат отбора;
- пустой список заметок, существующая и отсутствующая заметка;
- отсутствующая Markdown-публикация с возвратом к списку;
- пустой, отфильтрованный и готовый список промптов; загрузка, ошибка и отсутствующая запись;
- готовый музыкальный плеер, загрузка, воспроизведение, пауза, пустой плейлист, отказ браузера и ошибка аудиофайла.

## 12. Музыкальный плеер

- источники и порядок задаются в `src/data/playlist.ts`; текущая запись находится в `public/audio/mirostar-lofi-beats-531504.mp3`;
- воспроизведение начинается только после действия пользователя;
- одна кнопка переключает воспроизведение и паузу; пауза не сбрасывает позицию;
- после завершения автоматически запускается следующая запись, после последней — первая;
- недоступная запись пропускается, а перебор прекращается, если доступных файлов не осталось;
- доступны изменение громкости и повторная попытка после ошибки;
- дисплей показывает название записи, текущую позицию и длительность;
- ошибка загрузки объясняется на выбранном языке интерфейса.
- при размонтировании плеер останавливает активный элемент; автозапуск отсутствует.

## 13. Доступность

- семантические `header`, `nav`, `main`, `aside`, `footer`;
- skip-link переводит фокус на `main`;
- видимые подписи полей;
- `lang="ja"` на японских фрагментах;
- заметный `:focus-visible`;
- элементы управления не меньше 44 CSS px на mobile;
- компоновка работает при 320 px и увеличении текста до 200%.

## 14. Производительность

- manifest загружается один раз вместе с выбранной категорией;
- JSON других категорий не загружается до перехода;
- большая категория выдаётся порциями по 40 элементов;
- изображения и шрифты не должны блокировать чтение каталога.
- Markdown-публикации входят в статическую сборку и не требуют запроса к серверу во время чтения.
- Markdown-заметки входят в статическую сборку и не требуют запроса к серверу во время чтения.
- файл промпта загружается только при открытии его подробной страницы.

## 15. Проверки

- unit-тесты нормализации и поиска по русскому, кандзи и кане;
- unit-тесты frontmatter, поиска по заголовку и отбора по датам;
- unit-тесты локалей и форматирования дат;
- unit-тесты поиска промптов по названию, описанию и тегам;
- unit-тесты циклического перехода плейлиста, одного/пустого списка и пропуска ошибок;
- проверка схемы, количества, ID, порядка и ссылок на источники;
- TypeScript check;
- production build;
- механическая проверка дизайн-анти-паттернов.
