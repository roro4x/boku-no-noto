# Добавление контента на сайт

Добавляй материал в существующую архитектуру проекта, не меняя компоненты интерфейса без отдельной необходимости.

## Рабочий процесс

1. Определи целевой раздел по формулировке пользователя. Если раздел действительно неоднозначен и выбор изменит публичный маршрут, уточни его до записи файла.
2. Прочитай [references/content-formats.md](references/content-formats.md) и проверь актуальные соседние записи в целевой папке или каталоге данных.
3. Сохрани авторский текст без редакторских изменений, если пользователь не просил исправить, перевести или переформатировать его. Разрешены только технически необходимые оболочка, frontmatter и нормализация завершающего перевода строки.
4. Выбери короткий стабильный slug/id латиницей в `kebab-case`. До создания проверь отсутствие совпадений файлов, slug и id. Не перезаписывай существующую публикацию без явного запроса.
5. Используй указанную пользователем дату; если даты нет, используй текущую локальную дату в формате `YYYY-MM-DD`. Не выдавай предположительную дату за предоставленную пользователем.
6. Добавь только файлы и записи, обязательные для выбранного раздела.
7. Запусти `npm test` и `npm run build`. При сбое из-за добавленного материала исправь его; не маскируй ошибки ослаблением тестов.
8. В итоговом сообщении назови раздел, созданный slug/id и изменённые файлы.

## Границы

- Не добавляй один материал сразу в несколько разделов, если пользователь этого не просил.
- Не меняй порядок существующих записей вручную: Markdown-архивы сортируются по дате автоматически, а новые промпты добавляются в конец массива `prompts`.
- Не добавляй frontmatter в исходный файл промпта: его метаданные хранятся отдельно в TypeScript.
- Не коммить и не публикуй изменения без отдельного запроса.
